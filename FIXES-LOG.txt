COMMIT ff3e19b — fix: prevent duplicate grid fills via atomic order claims
================================================================================

FILE: lib/grid.ts
--------------------------------------------------------------------------------
- Added claimPendingOrder(): atomic pending -> filled UPDATE with .returning(),
  so only ONE caller wins a fill race.
- checkGridStopLoss: BOTH long and short branches now claim BEFORE placing the
  market close. Previously the short branch had no claim at all, and the long
  branch placed the exchange order first — so overlapping ticks / the 20s risk
  check could both fire a close (a second close-long OPENS A FRESH SHORT).
- Removed the empty catch{} that swallowed a failed exchange close and went on
  to book a phantom closure. On failure the claim is REVERTED so a later tick
  retries.
- Added clampClosePrice(): guards computed TP / buy-to-close targets against
  <= 0 (a cheap coin with wide spacing produced a non-positive target).
- Naked-sell (COMBO short open) fill now claims the row atomically before
  inserting the paired buy-to-close tracking row.
- COMBO short close replaced the read-then-write "fresh status" check (a
  non-atomic check-then-act) with claimPendingOrder.
- isCombo now uses effectiveDirection(gc) instead of the raw gc.direction, so
  direction: "auto" grids take the COMBO branches (they were being treated as
  one-sided — the short-close was skipped and re-processed as a fresh LONG).
- checkAllHeldPositionsRisk: entry fee basis is now per-symbol (maker vs taker)
  read from isMakerSymbol(gc), instead of booking maker fees on taker entries.
- Removed the [CancelOp] Line ~NNN debug log spam and the misleading sellPrice
  log in the COMBO branch.

VERIFY: grep -n "claimPendingOrder" lib/grid.ts   -> multiple hits

COMMIT ac6d13b — fix: correct advisor scoring, Ondo-DNA drift gate,
                  and grid sizing bugs
================================================================================

FILE: lib/advisor.ts
--------------------------------------------------------------------------------
BUG 1: heuristicScore short branch used `1 - crossover`. crossover is -1|0|1, so
       that produced {0,1,2} — ALWAYS >= 0 — while long produced {-1,0,1}.
       Shorts were systematically scored above longs for the same signal.
BUG 2: volSurge arrives normalized to [-1/3, 1] but the code assumed a RAW
       multiple: ((f.volSurge)*100 - 1.5)*0.4 => range [-13.8, 39.4], saturating
       the sigmoid and collapsing the score to a near-constant.
BUG 3: recordOutcome was a non-atomic read-modify-write (lost updates under
       concurrent graders, incl. multi-instance Fly).
BUG 4: sampleBeta could return NaN for tiny integer shapes.
FIX: Negate the short branch; rescale volSurge; single atomic jsonb UPDATE for
     stats; NaN -> prior-mean fallback.

VERIFY: grep -n "jsonb_build_object" lib/advisor.ts


FILE: lib/combo-score.ts
--------------------------------------------------------------------------------
BUG 1: `if (absDrift > driftThreshold && !isOndoDna)` — the !isOndoDna made the
       drift gate a NO-OP for exactly the coins it was meant to loosen (they
       were only stopped by hard gate 1 at 20%, never at 15%).
BUG 2: comboDna had no guard for empty/short candle arrays (candles[n-1].close
       throws on n=0; every ratio is meaningless at n=1).
BUG 3: suggestLeverage could return up to 20x, but grid.ts refuses to build any
       ladder above MAX_GRID_LEVERAGE = 5 — a guaranteed no-build.
FIX: Remove the !isOndoDna guard; add n < 2 early return; clamp leverage to 5.

VERIFY: grep -n "MAX_GRID_LEVERAGE" lib/combo-score.ts


FILE: lib/grid-sizing.ts

BUG 1: Paper-mode snapshot query had NO mode filter, so a live snapshot written
       more recently than the last paper one sized PAPER grids against live

BUG 2: The exposure clamp could push budgetPct BELOW the minimum that funds even
       one order (e.g. $3 balance at 5x: floor 10%, cap 6.5% -> 6.5%), recreating
       "budget too small despite free balance".
BUG 3: MAX_GROSS_EXPOSURE_PCT was hardcoded, duplicating the env-overridable
       EXPOSURE_LIMITS limit.
FIX: Filter snapshot on eq(equitySnapshots.live, false); re-apply the notional
     floor after the clamp; read the cap from EXPOSURE_LIMITS.

FILE: lib/grid.ts (final batch)
--------------------------------------------------------------------------------
BUG 1 (HIGH): cancelOtherPendingOrders marked EVERY other pending row
       `cancelled` after a stop-loss — including rows with buyPrice set, i.e.
       OTHER HELD RUNGS. Their positions stayed open on the venue with no
       tracking record, so the orphan sweep later force-closed them at market
       WITHOUT booking a trade (silent PnL loss).
FIX: Split into naked (buyPrice == null -> cancel on venue + DB) and held
     (buyPrice != null -> LEAVE TRACKED; logged; each has its own per-rung SL).

BUG 2 (HIGH): setupGrid's cleanup was gated on `cfg.mode === "live" && exchange`,
       but every maker call site passes exchange as undefined
       (setupGrid(cfg, gc, snap, vol, undefined, true)). So live maker rebuilds
       took the PAPER branch: rows cancelled in the DB while the REAL resting
       orders stayed live on the venue — orphans on every rebuild.
FIX: Gate on cfg.mode === "live" only, resolving a client when not supplied;
     cancel only naked rows (held rows are open inventory, not rebuild fodder).

BUG 3: The COMBO short-close wrote paperBalance with NO paper-mode guard (every
       sibling path wraps it in if (cfg.mode === "paper")). In live mode a
       realized short-close PnL was credited to the PAPER book — which the risk
       layer then reads as its equity baseline.
FIX: Wrapped in if (cfg.mode === "paper").

BUG 4: syncExchangeState marked a venue-FILLED resting order as `filled` in the
       DB without ever setting buyPrice, booking the entry, or arming the paired
       follow-up. The row dropped out of getActiveOrders (pending-only) and out
       of checkAllHeldPositionsRisk (buyPrice-not-null) — a real filled position
       silently lost, then force-closed by the orphan sweep.
FIX: Fills are DEFERRED to the poller (which claims atomically and settles).
     Cancellations are still mirrored (safe — no position exists). Filled rows
     now log at ERROR level and are left pending.

VERIFY: grep -n "HELD-ROW SAFETY" lib/grid.ts
        grep -n "FILL DEFERRED" lib/grid.ts


FILE: lib/engine.ts
--------------------------------------------------------------------------------
BUG 1 (HIGH): The flash-fade loop hardcoded
       { enabled: true, minMovePct: 20, minVolumeMultiplier: 5,
         positionSizeUsdt: 300, leverage: 3, maxPositions: 2 }
     with an unconditional enabled: true — bypassing the FlashFadeConfig type
     entirely, so NOTHING could turn it off — and sizing a $300 x 3x = $900
     NOTIONAL position on EVERY enabled grid symbol on any >20%/5x-volume move.
     On a sub-$500 account that is larger than the whole grid budget. Paper mode
     fabricated PnL; live mode was a live-money hazard on every pair.
FIX: Single module-level FLASH_FADE config read from env, DEFAULT OFF
     (FLASH_FADE_ENABLED=1 to enable), all params env-tunable
     (FLASH_FADE_SIZE_USDT, _LEVERAGE, _MIN_MOVE_PCT, _MIN_VOL_MULT,
     _MAX_POSITIONS). When disabled we also skip the per-symbol 50-candle fetch.

BUG 2: reconcilePositions() ran BEFORE the `status !== "running"` check, so while
       the bot was STOPPED the 60s tick kept marking DB positions closed whenever
       the venue did not report them — and that path books NO trade row and NO
       PnL, so the realized result silently vanished from the books and from ML
       training, every 60s, for as long as the bot stayed stopped.
FIX: Moved AFTER the status gate (so the normal close / soft-stop / native-stop
     paths have had their chance). Log is now error level and explicitly says no
     PnL was recorded, including entry and size.

BUG 3: initRealtimeEngine ran ONCE at process start, only for grids enabled at
       that moment. A grid enabled LATER (AI advisor, rotation, manual toggle)
       never got a price poller, so livePrices[symbol] stayed undefined and
       checkAllHeldPositionsRisk (the 20s stop, and the ONLY periodic stop for
       short inventory) silently skipped every one of its held rungs.
FIX: Extracted an idempotent ensurePricePolling(symbol) and call it for every
     grid symbol at the top of the grid loop. Also fixed the poller capturing
     cfg.exchange once at construction — it now refreshes the venue every 60s.

BUG 4: The paper kill-switch divisor could be 0/missing, making the drawdown
       ratio NaN/Infinity so the switch never fired.
FIX: Guard _ksStart > 0.

DEAD CODE: removed the unused MexcWebSocketManager import (never constructed —
     the REST poller is the real feed).

VERIFY: grep -n "FLASH_FADE_ENABLED" lib/engine.ts
        grep -n "ensurePricePolling" lib/engine.ts


FILE: lib/portfolio-sizing.ts
--------------------------------------------------------------------------------
BUG: minBudgetPctForNotional was (MIN_NOTIONAL * sidesPerLevel * 100) /
     availableBalance — `levels` dropped from the numerator and `leverage` from

FIX: (MIN_NOTIONAL * levels * sidesPerLevel * 100) / (availableBalance * leverage)
